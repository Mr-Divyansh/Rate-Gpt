# Security controls

- The Government of India OGD / AGMARKNET API key is read only from a server-side environment variable and is never included in browser code.
- Web3Forms access keys are public form identifiers, not account passwords or secret API credentials. The website submits the contact form directly from the browser as recommended by Web3Forms; the key is supplied at build time through `VITE_WEB3FORMS_ACCESS_KEY` and is expected to be visible in the browser bundle.
- Zod caps and validates public filters and contact fields; JSON and URL-encoded bodies are limited to 32 KB.
- Helmet, compression, server-generated request IDs, and Express rate limits are enabled in `server.ts`. The CSP permits same-origin scripts and Google Fonts, blocks inline style attributes with `style-src-attr 'none'`, and does not permit inline scripts or `unsafe-eval`. Dynamic price bars use CSSOM style properties rather than HTML style attributes.
- Vercel applies CSP, HSTS, frame protection, MIME sniffing protection, a strict referrer policy, and a restrictive Permissions-Policy to static responses through `vercel.json`.
- Live-data, metadata, and commodity routes have a stricter process-local rate limit than general API routes. The optional server-side contact proxy has a low process-local limit, but the public browser-to-Web3Forms submission does not pass through Express; provider-side spam controls and domain restrictions are required for that path.
- Express rate limits use the process-local default store. They constrain each function instance but are not a globally shared quota across Vercel instances. Vercel Firewall additionally enforces a fixed-window rate limit on `/api/v1/`: 100 requests per 300 seconds per IP + JA4 counting key. Vercel documents that WAF counters are per region, so this is an edge-level control, not one perfectly global counter.
- API caching is endpoint-specific. Public read-only price routes use a 60-second shared edge TTL, location metadata uses 15 minutes, and commodity suggestions use 5 minutes. Browser caching is disabled/revalidated for these responses. Contact, health, sync-status, and other non-cacheable responses retain the default `no-store` policy. No persistent price store or historical cache exists.
- The public contact form requires explicit consent and includes a honeypot. It sends directly to Web3Forms from the browser because Web3Forms blocks ordinary server-side submissions unless the account is on Pro and the server IP is allowlisted. Its public provider submission is outside the site's `/api/v1/` WAF rule and requires provider-side spam/domain controls.
- The optional `POST /api/v1/contact` server proxy remains for deployments that meet Web3Forms' Pro-plan and server-IP safelist requirements. It is not used by the public contact page.
- Production errors return safe error envelopes without credentials, upstream bodies, request payloads, or stack traces. Server logs use only bounded request identifiers and error names/codes.
- Contact submissions are forwarded to Web3Forms and are not written to a Rate-GPT database. The provider/account retention duration has not been verified and is not stated as a fixed period.

The deployed static pages are served by Vercel, while `server.ts` protects the API function. A production response-header scan and Web3Forms retention review require provider/account access and are not inferred from source code. The WeatherAPI client key is intentionally public in the browser bundle. It is supplied only through `VITE_WEATHERAPI_KEY`; the source-code fallback has been removed. Restrict the key through WeatherAPI account controls and never reuse it as a server-side secret. Provider-side referrer/quota restrictions cannot be enforced by this repository.
